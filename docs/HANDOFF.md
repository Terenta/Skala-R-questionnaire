# Передача проекта разработчикам

## Готовое сообщение

Коллеги, передаю готовую систему анкетирования для исследования восприятия нашей компании.

Репозиторий: `git@github.com:Terenta/Skala-R-questionnaire.git`

В составе проекта:

- публичная адаптивная анкета;
- автоматическое сохранение после каждого выбора и изменения текста;
- локальная страховка в браузере при обрыве сети;
- автоматическая повторная отправка после восстановления соединения;
- защищённый дашборд аналитики;
- раздельная аналитика текущей схемы `v2` и ранее сохранённых ответов `v1`;
- хранение ответов в постоянном Docker volume;
- атомарная запись, контроль ревизий и журнал изменений;
- резервное копирование и проверки целостности.

Что требуется:

1. Развернуть проект через Docker Compose на вашем сервере.
2. Создать `.env` на основе `.env.example` и установить собственные логин и длинный пароль для аналитики.
3. Подключить домен и HTTPS.
4. Настроить reverse proxy на корне отдельного домена либо по пути `/reputation/`. При размещении по пути префикс `/reputation` нужно удалять перед передачей запроса приложению.
   Если reverse proxy работает в Docker, закрепить `COMPOSE_FILE=docker-compose.yml:docker-compose.shared-network.yml` и имя общей сети в production `.env`.
5. Не удалять Docker volume `reputation-survey-data` при обновлениях.
6. Установить почасовой бэкап и выгружать копии во внешнее хранилище.
7. Генератор 50 демонстрационных ответов запускать на production только осознанно и после резервного снимка; он работает лишь с зарезервированными тестовыми идентификаторами и не должен заменять реальные ответы.

После развёртывания необходимо проверить:

- сохранение после каждого выбора;
- восстановление заполнения после перезагрузки;
- сохранение после временного отключения сети;
- полное и досрочное завершение;
- доступ к аналитике только после авторизации;
- состояние `/health`;
- сохранность данных после пересоздания контейнера;
- создание и тестовое восстановление бэкапа.

Не меняйте механику автосохранения, ревизий и атомарной записи без повторного аварийного тестирования. Эти механизмы защищают ответы от потери и перезаписи устаревшими запросами.

Полная инструкция, конфигурации Nginx/Caddy, команды бэкапа и приёмочный чек-лист находятся в README.

## Что сказать на созвоне

Короткая версия:

> Это автономное Node.js-приложение без внешней базы и npm-зависимостей. Актуальная версия каждой анкеты хранится отдельным JSON-файлом в постоянном Docker volume, а каждая принятая ревизия дополнительно попадает в журнал. Браузер сохраняет черновик локально и повторяет отправку после восстановления сети. При обновлении можно пересоздавать контейнер, но нельзя удалять volume. Аналитику необходимо закрыть HTTPS и собственным паролем. Перед приёмкой обязательно проверить восстановление из бэкапа.

## Вопросы разработчикам

1. Какой production-домен и URL будут использоваться?
2. Reverse proxy работает на хосте или в Docker?
3. Куда будут выгружаться внешние резервные копии?
4. Кто получает доступ к аналитике и где будут храниться секреты?
5. Какая система мониторинга будет проверять `/health`, место на диске и возраст последнего бэкапа?
6. Кто отвечает за тест восстановления и с какой периодичностью он выполняется?

## Критерии приёмки

Работа считается принятой, когда разработчики передали:

- production URL анкеты;
- URL аналитики;
- подтверждение HTTPS;
- результат healthcheck;
- результат `audit-data.js`;
- подтверждение сохранения после пересоздания контейнера;
- имя и время последнего бэкапа;
- успешный результат тестового восстановления;
- описание внешнего хранилища резервных копий;
- контакт ответственного за эксплуатацию.
